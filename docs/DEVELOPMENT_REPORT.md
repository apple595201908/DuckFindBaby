# 《鴨鴨基因實驗室》Ver1.0 網頁版開發報告

## 1. 專案摘要

《鴨鴨基因實驗室》是一款手機優先的快速顏色判讀網頁遊戲。玩家觀察兩隻親代鴨的顏色，在候選鴨從實驗艙底部跳起、落回底部前，選出符合混色規則的寶寶。越早作答，單題分數越高；答錯或超時會立刻結束該次遊戲。

- 完成版本：Ver1.0 網頁版
- 主要平台：iPhone Safari、Android Chrome、手機與平板瀏覽器
- 公開網址：<https://duckling-family-match.yoyo50582.chatgpt.site>
- 發布形式：響應式網站、PWA 離線快取、GitHub 原始碼專案
- 停止範圍：Android APK 封裝不再維護，後續以網頁版為唯一主要版本

## 2. 開發目標

1. 讓玩家能快速辨識顏色，而不是被漸層、反光或相似選項干擾。
2. 把「剩餘時間」直接轉化為鴨子的高度，移除額外秒數進度條。
3. 在不同手機、瀏海螢幕與平板比例上維持大字、大鴨子及足夠觸控範圍。
4. 以低負載動畫維持流暢體驗，避免高解析裝置因模糊、陰影或重排而掉幀。
5. 提供可離線啟動的完整資產，不依賴遠端圖片、字型或音樂檔案。
6. 建立可測試、可註解、可交接並適合 GitHub 個人倉庫維護的專案結構。

## 3. 技術架構

| 層級 | 技術 | 用途 |
|---|---|---|
| 網站外層 | React 19、TypeScript | 提供網站入口與全螢幕遊戲框架 |
| 建置系統 | Vinext、Vite 8 | 開發伺服器與正式建置 |
| 遊戲核心 | HTML5、CSS、Vanilla JavaScript | 回合、輸入、動畫、音效與畫面 |
| 離線能力 | Service Worker、Web App Manifest | 快取程式與素材，支援 PWA |
| 音訊 | Web Audio API | 即時合成 BGM 與提示音，不載入外部音樂 |
| 測試 | Node.js Test Runner、ESLint | 驗證規則、畫面契約與程式品質 |
| 發布 | Cloudflare Worker 相容輸出 | 託管公開網站 |

遊戲將純規則與瀏覽器操作分離：

- `public/game/engine.js` 只處理色票、配方、候選生成、速度與計分。
- `public/game/game.js` 處理狀態、DOM、輸入、音效、暫停與回合切換。
- `public/game/game.css` 處理響應式排版、鴨子精靈圖、跳躍及答題回饋。

這種分層讓規則可在沒有瀏覽器的環境直接測試，也降低 UI 修改破壞混色邏輯的風險。

## 5. 核心遊戲流程

遊戲使用明確的階段狀態：

1. `menu`：首頁與規則入口。
2. `countdown`：先生成並顯示第一題，再播放 3、2、1、GO。
3. `playing`：同一批已鎖定的親代與候選開始跳躍，接受輸入。
4. `resolving`：停止重複輸入，播放答對回饋並準備下一題。
5. `gameover`：答錯或逾時，揭示正解並顯示結算。

每次清除或重開回合都會增加 `token`。所有延遲函式與動畫回呼會比對 token，舊回合的回呼因此無法誤改新回合。這是避免快速重試、返回首頁或暫停時產生重複計分的重要保護。

開局第一題會在倒數開始前由 `prepareRound()` 生成並由 `renderPreparedRound()` 顯示。GO 之後只執行 `launchPreparedRound()`，不會再次抽題，因此預覽與正式題目完全相同。

## 6. 跳躍時間與計分

候選鴨從選項框底部出現，在動畫進度 14% 到達最高點，隨後立即下降。選項框使用 `overflow: hidden` 裁切，鴨子最後從自己的實驗艙底部消失，不會穿出卡片。

回合時間依總分縮短：

```text
duration = max(1600, round(3800 - score × 6.5)) 毫秒
```

- 0 分：3.8 秒
- 50 分：約 3.475 秒
- 100 分：約 3.15 秒
- 200 分：約 2.5 秒
- 300 分：約 1.85 秒
- 最快：1.6 秒

下降進度不是單純線性高度，而是使用 `DESCENT_POWER = 1.45` 對應 CSS 的視覺下降曲線。程式將下降位置切成十等份：

```text
band = min(9, floor(descentPosition × 10))
score = 10 - band
```

最高區獲得 10 分，最低區獲得 1 分。鴨子的位置就是玩家可見的時間資訊，因此沒有另一條秒數進度條。

## 7. 難度設計

難度由兩個維度平滑提升：

1. 總分越高，單題跳躍週期越短。
2. 每四回合增加一個候選，從三個開始，最多六個。

候選數公式：

```text
candidateCount = min(6, 3 + floor((round - 1) / 4))
```

此設計讓新玩家先熟悉配方，再逐步增加視覺搜尋壓力；速度設有下限，避免長時間遊玩後變成無法反應的純運氣。

## 8. UI 與行動裝置適配

- 使用 `100dvh` 填滿瀏覽器實際可用高度。
- 使用 safe-area inset 避開瀏海、動態島、圓角與底部手勢列。
- 直向模式採兩欄候選艙，三或五個選項的最後一格自動置中。
- 橫向模式壓縮 HUD 高度，將更多空間留給親代鴨與候選鴨。
- 字體、卡片、按鈕及觸控範圍採 `clamp()`，同時設定最小與最大尺寸。
- 候選鴨、正確／錯誤回饋及提示文字具有明確視覺層級。
- 色彩輔助模式會顯示符號與顏色名稱，不只依賴色相判斷。
- 鍵盤支援數字鍵 1–6，Esc 可暫停或繼續。
- `aria-label` 與 live region 提供基本螢幕閱讀器資訊。

## 9. 美術與素材流程

鴨子以單一基礎姿勢建立 14 色圖集。身體使用鎖定色號，眼睛、嘴喙、腮紅、腹部與腳保持固定，讓玩家能集中判斷身體顏色。

`scripts/generate_gene_palette_sprites.sh` 會：

1. 取得基礎鴨子。
2. 建立身體區域遮罩。
3. 套用 14 個鎖定色號。
4. 保留固定五官及腹部。
5. 清除每格左上角的非透明區域。
6. 組成 4×4 PNG 精靈圖。
7. 驗證所有已使用格子的透明角落，防止黑色方框再次出現。

背景已完全移除愛心反應爐與高細節實驗室場景，改為淡藍至淡紫的低對比 CSS 漸層。單一大型 DNA 雙螺旋使用透明 PNG 疊加，視覺尺寸為 `118vmax`、透明度 `0.14`，以 28 秒的慢速 `transform` 做輕微漂移、縮放與旋轉。此圖層固定在所有選單後方、設定 `pointer-events: none`，不參與碰撞或輸入，也不使用高成本即時濾鏡。

## 10. 音效與 BGM

音訊由 Web Audio API 即時合成，不需要下載外部音樂檔：

- 倒數：短促方波提示。
- 開始：三音上行提示。
- 答對：明亮三角波和弦。
- 答錯／逾時：較低頻的下降音。
- BGM：旋律、低音及裝飾音分開排程。

BGM 速度會隨分數提高，最高限制為 150 BPM。瀏覽器要求使用者先互動才能啟用音訊，因此 AudioContext 在按下開始或聲音按鈕後建立。

## 11. 效能策略

- 動畫只改變 `transform` 與 `opacity`，避免逐幀修改尺寸或位置屬性。
- 使用 `requestAnimationFrame` 檢查截止時間，不強迫瀏覽器同步重排。
- 移除即時模糊、`backdrop-filter`、大型移動陰影與多層水面動畫。
- 使用 CSS containment 限制排版與繪製影響範圍。
- 事件委派只在候選網格註冊一個 `pointerdown` 監聽器。
- 鴨子精靈圖使用固定百分比位置，避免不同 WebView 對 CSS 計算式支援差異。
- 回合結束後取消動畫幀、音樂排程及計分動畫，避免殘留工作。

## 12. PWA 與快取

Service Worker 在安裝時預先快取遊戲 HTML、CSS、JavaScript、Manifest 與必要圖片。頁面導覽採網路優先，失去網路時退回快取；其他靜態資源採快取優先。

每次修改可執行程式或圖片 URL 時，必須同步：

1. 更新 HTML、CSS、JavaScript 與外層 iframe 的查詢版本。
2. 更新 `sw.js` 內的資產 URL。
3. 增加 `CACHE_NAME`。

這項規則能避免手機繼續載入修正前的舊鴨子圖或舊程式。

## 13. 主要問題與修正紀錄

| 問題 | 根因 | 修正 |
|---|---|---|
| 高解析平板嚴重卡頓 | 舊封裝強制軟體繪圖及高成本濾鏡 | 網頁恢復 GPU 友善動畫，移除模糊與強制重排 |
| 首頁與鴨子旁出現黑方塊 | 舊精靈圖快取與透明角落素材 | 重新生成透明素材、逐格驗證並更新快取版本 |
| 開局預覽與正式第一題不同 | 倒數結束後才抽第一題 | 倒數前準備並鎖定題目，GO 後只啟動動畫 |
| 相似色同時出現在答案列 | 干擾項只排除正解重複 | 對完整候選集合進行相似色兩兩互斥 |
| 鴨子下降後穿出選項框 | 動畫圖層未在艙內裁切 | 新增獨立 viewport 與 `overflow: hidden` |
| 答對／答錯不明顯 | 卡片回饋只改小範圍顏色 | 加入整卡綠／紅光、勾叉徽章與正解揭示 |
| DNA 背景干擾選單 | 前景裝飾層級與對比過高 | 降低透明度、禁止指標事件並固定在背景層 |
| 背景仍有愛心主視覺 | 舊場景圖直接作為遊戲底圖 | 移除場景引用，改用淡色漸層與單一大型 DNA 雙螺旋 |

## 14. 測試與品質門檻

主要驗證命令：

```bash
npm run lint
npm run test
git diff --check
```

測試涵蓋：

- 12 組配方的決定性與親代順序互換。
- 14 個鎖定色號。
- 正解唯一性與相似色互斥。
- 候選數量提升規則。
- 速度曲線與 1.6 秒下限。
- 下降十等份計分。
- 必要離線素材存在。
- 無秒數進度條、使用鴨子動畫當回合時鐘。
- 候選艙裁切、答對與答錯回饋。
- 響應式直向與橫向規則。
- 開局題目在倒數前鎖定，不會於 GO 後重新抽題。

## 15. GitHub 專案交付規格

GitHub 專案包應包含：

- 原始碼、素材、文件、Skill、測試及 `package-lock.json`。
- 清楚的 `README.md`、本開發報告與配色規格。
- 可重建素材的生成腳本。

應排除：

- `.git`、`node_modules`、`dist`、`.next`。
- `.sites-runtime`、`.wrangler`、記錄檔及快取。
- `.env`、私密金鑰與本機設定。
- APK、停止維護的 Android 封裝及其測試。

解壓縮後執行 `npm ci`、`npm run lint`、`npm run test`，即可確認環境與專案是否完整。

## 16. 後續維護原則

1. 網頁版為唯一主線，不重新加入 APK 工作流，除非產品方向再次明確變更。
2. 新配方必須先確認目標色、相似色群及辨識公平性。
3. 動畫時間、CSS 關鍵影格與計分公式必須一起修改。
4. 任何破圖修正都要同時考慮素材透明度與瀏覽器快取。
5. 主要邏輯要留下「為什麼這樣設計」的註解，不以逐行翻譯程式碼取代文件。
6. 所有功能修改完成後，更新測試、README、開發報告及版本包。
